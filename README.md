# Nightfall Ops — WyteGames

React 18 + TypeScript + Phaser 3 + Vite + Capacitor 6 arcade shooter. Gameplay and procedural audio are offline-first; fonts and visual assets are bundled locally. The project uses a React-only HUD and Phaser for the world simulation.

## Run locally

Requires Node.js 20+.

```sh
npm install
npm run dev
npm run build
```

## Android setup

The Android platform is generated by Capacitor; do not create a partial `android/` directory manually.

```sh
npm install
npx cap add android   # first time only
npm run build
npm run android:sync  # after platform generation; syncs plugins then applies native config
```

`scripts/configure-android.mjs` sets `android:screenOrientation="sensorLandscape"` and installs an immersive sticky `MainActivity`. Capacitor App handles the Android Back button as pause/resume/navigation. Capacitor Haptics is optional and can be disabled in Settings. Build/install the APK and verify orientation, fullscreen, Back handling, and haptics on a real device.

## Controls

- **Mobile:** pointer-capture joystick; drag the right thumb to aim and hold FIRE; BOMB, STEALTH, FOCUS, and optional MAGIC actions.
- **Laptop:** WASD/arrows move, mouse aim/click or Space fires, Shift sprints, C stealths, Q switches Assault/Shotgun, E bomb, Escape pauses.
- **Gamepad:** left stick movement and primary-button firing are supported.
- **Modes:** Campaign (secure cache + commander), Survival (five waves + final commander), Rescue (find captive + escort to exit + commander), Sabotage (plant/defend beacon + commander).

## Saves and migrations

IndexedDB is the primary local save; localStorage remains a compatibility snapshot. Legacy profiles are normalized by merging missing fields into defaults rather than wiping them. Settings and inventory are hydrated from the stored profile. A confirmed reset only resets the local profile; it does not delete a cloud backup.

## Google account cloud backup

Configure `VITE_GOOGLE_CLIENT_ID` from `.env.example`, enable Google Drive API, and authorize the correct OAuth origin in Google Cloud Console. The app stores `nightfall-ops-save.json` in the signed-in account's private Google Drive `appDataFolder`; no folder ID is needed. The profile contains progress, coin balance, settings, inventory, and mission/activity/purchase histories.

Writes are debounced and serialized, with one request in flight. Per-field timestamps choose the newest value during conflicts; coin balances are not merged with `Math.max`. Background sync does not open a sign-in popup after token expiry; the player must tap the account button to reconnect. The header account button uses `@capacitor-firebase/authentication`: Android invokes the native Google account picker, while the plugin supplies its web Google sign-in flow in supported browsers. The Firebase UID is the server wallet key; the server verifies Firebase ID tokens. The supplied `google-services.json` is included at repository root and `android:configure` copies it to `android/app/`. Before testing the native picker, add your release/debug SHA-1 fingerprints in Firebase Console → Project settings → Android app, enable Google under Authentication → Sign-in method, then download the refreshed `google-services.json` (the uploaded file has no OAuth client entries yet). Keep the Android package ID `app.nightfallops.vercel` identical across Capacitor and Firebase. The separate Google Drive backup still uses Google Identity Services and is optional; wallet login does not depend on Drive OAuth.

## Purchases and entitlements

**Payment/billing is deliberately not implemented in this client.** `purchaseProvider` is an interface stub for UI requests only; the shop displays prices but cannot grant paid partners or armies. Paid entitlements must be returned by a trusted server after its own payment verification. No payment keys, SDKs, webhooks, or client-side paid entitlement grants are included.

## Audio and performance

Audio is generated locally using Web Audio: master/music/SFX buses, compressor, cached noise buffers, location ambience, combat intensity, and procedural weapon/UI/impact sounds. Trees, logs, rocks, and ferns are reused from a small local texture set. Settings include volume, haptics, aim assist, camera shake, reduced-motion preference, FPS estimate, and action-control positioning.

## Catalog, upgrades and weapons

- `src/catalog.ts` is the only source for shop prices, upgrade cost curves and weapon combat stats. The catalog defines the NGN/USD display rate constant (`NGN_PER_USD = 1200`).
- The weapon shelf and weapon detail modal use the same catalog objects consumed by `src/game.ts`; run `npm run test:catalog` for price/stat/cost-curve checks.
- Operator upgrade levels and owned coin-purchased weapons are persisted in the existing profile. Older `weaponLevel` profiles migrate to the Assault Rifle unlock when appropriate; other saved fields are retained.
- `src/purchaseProvider.ts` is deliberately an inert interface stub. `startCheckout()` returns `checkout not connected`; `getEntitlements()` returns an empty list until the separate server provider is wired. Do not add payment keys, Flutterwave SDKs, webhooks, or client-side grants here.

## Server-authoritative wallet and payments (required for production)

The client-side profile is for presentation/settings only. Paid products and coin purchases must be verified by the Firebase Functions economy service; never use a local `coins` value as proof of balance. This archive adds `functions/` (Firebase Admin + Firestore transactions), a server-owned wallet ledger, idempotent spend requests, Flutterwave hosted checkout, and webhook verification. The Android `google-services.json` config identifies Firebase project `nightfall-b49be` and package `app.nightfallops.vercel`; it is client configuration, **not** a payment secret or service-account credential.

1. Install Firebase CLI and log in, then select the `nightfall-b49be` Firebase project. Enable Firestore and deploy `firestore.rules` (these rules intentionally deny all client reads/writes to wallet/payment collections). The first authenticated wallet request creates `nightfallWallets/{firebaseUid}` and a minimal `nightfallProfiles/{firebaseUid}` record.
2. Enable Google in Firebase Authentication and configure Android SHA-1 fingerprints so the native Google account chooser can authenticate. The backend verifies Firebase ID tokens with Firebase Admin; it no longer expects a Google Drive access token. Add a Firebase web app config if you also need web-browser sign-in.
3. Set client env `VITE_ECONOMY_API_URL=https://us-central1-nightfall-b49be.cloudfunctions.net/economy` and redeploy the web app / rebuild the APK. This is the economy URL: it is the HTTPS URL of the deployed `economy` Cloud Function, not a Firebase Console page.
4. Set Functions secrets: `firebase functions:secrets:set FLW_SECRET_KEY` and `firebase functions:secrets:set FLW_WEBHOOK_HASH`. Set runtime env `ALLOWED_ORIGIN` to the exact production origin and `PAYMENT_REDIRECT_URL` to the deployed payment-return page. Do not commit these values.
5. Deploy: `cd functions && npm install`, then from repository root run `firebase deploy --only functions,firestore:rules`. Configure Flutterwave webhook URL as `https://us-central1-nightfall-b49be.cloudfunctions.net/economy/webhook` and the matching webhook hash in Flutterwave.
6. Before launch, wire every spendable UI action to `serverEconomy.spend` and hydrate the displayed balance from `serverEconomy.wallet` after sign-in/payment return. The weapon and upgrade paths use the server API in this version; the local-only daily reward, mission rewards, recruitment and supplies UI are not yet all migrated. Do not ship monetized production until those remaining coin-changing paths are moved to server transactions and a payment-return wallet refresh is added.

The server checkout is NGN-only, derives amounts from a server-side product catalog, and grants items only after the Flutterwave webhook verifies the transaction with Flutterwave's API. This source currently uses Flutterwave Standard's `/v3/payments` and `/v3/transactions/{id}/verify` endpoints; do not label it a Flutterwave API v4 implementation until those endpoints are replaced with and tested against your account's supported v4 contract. Never trust the redirect query parameters as proof of payment. Test with Flutterwave test credentials first. No service account JSON or secret keys are bundled.


## Standalone APK/AAB diagnostics

- A top-level React error boundary catches render crashes and offers a recovery/reload screen plus a diagnostic JSON export. Global JavaScript errors, unhandled promise rejections, network changes, app visibility changes and wallet refresh failures are recorded in a bounded local diagnostic log. Logs are kept on-device and are not uploaded automatically.
- Open **Settings → Standalone APK / AAB diagnostics → Run checks** to test online status, local storage, Firebase session, canvas state and the HTTPS economy health endpoint. Use **Export diagnostics JSON** when reporting a failure. The report contains runtime/device dimensions and recent diagnostic events; review it before sharing.
- `GET https://us-central1-nightfall-b49be.cloudfunctions.net/economy/health` reports service health and only booleans for payment-secret presence. It does not prove Flutterwave authentication or payment settlement works; those need test transactions.
- Run `npm run android:diagnose` after generating the Android platform. It checks package alignment, orientation, Google OAuth config, build output and economy URL without printing environment values. Warnings are expected before `npx cap add android`, `npm run build`, and the OAuth config is refreshed.

## Flutterwave server credentials

Configure the following Firebase Functions secrets through the Firebase CLI prompts. Do not paste them into `.env`, `VITE_` variables, source code, or GitHub files:

```sh
firebase functions:secrets:set FLW_CLIENT_ID
firebase functions:secrets:set FLW_SECRET_KEY
firebase functions:secrets:set FLW_ENCRYPTION_KEY
firebase functions:secrets:set FLW_WEBHOOK_HASH
```

The backend binds these four server-only secret names and the health endpoint reports only whether each value is present. Hosted checkout must remain server-initiated; do not collect card data in the game WebView or send credentials to the client. **Important billing status:** the checkout/verification calls inherited by this version still use Flutterwave Standard v3 endpoints. The client ID and encryption key are stored server-side for the account's approved v4/direct-charge migration, but are not used by those legacy v3 hosted-checkout calls. This archive does not claim a verified Flutterwave v4 API implementation; confirm the exact v4 endpoint and token contract for the merchant account before switching production traffic.

For native Android failures that occur before the JavaScript app can start (native plugin crashes, Gradle/manifest errors, process death), export the in-app report if it opens. Otherwise capture Android logs with `adb logcat -c` then `adb logcat -d > nightfall-logcat.txt` immediately after reproducing the issue. JS diagnostics cannot observe a process crash that happens before the WebView starts.
